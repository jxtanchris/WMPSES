# 3D 全景底图测试包（WMPSES）

这里是你「🌐 更换 3D 底图」功能可以直接用的 **360° 全景底图**，
全部按系统 3D 引擎的取图规则渲染：**等距柱状投影（Equirectangular）、宽:高 = 2:1**。

用一句话理解：把这张图横向首尾相接贴成一个球，你站在球心，
**画面正中间（50%）就是系统默认视角的正前方，画面正中横线就是地平线**。
横向左右边缘可以无缝衔接，转 360° 不会看到接缝。

## 四、热点对不齐怎么办

图里的设备是按系统坐标画的，但底图的"视点"和实时 3D 相机位置毕竟不是同一个点，
环绕、缩放到某些角度时，热点圆标可能和画面里的设备差一点。

处理办法（就是你说的命题管理员标点流程）：

1. 保持「🛠 题库与标点」模式；
2. 在 3D 画面上**按住鼠标左键拖动**闪烁的热点圆标，拖到画面对应设备上；
3. 点 **「💾 保存并同步题库」**，新的 3D 坐标会写回题库。

## 五、常见问题

**Q：上传后没反应 / 刷新又变回去了？**
A：换底图只是改了内存里的题库，必须再点 **「💾 保存并同步题库」** 才写数据库；
   如果后台服务没启动（`http://127.0.0.1:8765`），会退回浏览器本地缓存，换台电脑就看不到。

**Q：图片要求多大？**
A：JPG / PNG / WebP 都行，建议 **2:1 宽高比**、宽度 2048～4096。
   现在的 A 图 719 KB，存进 SQLite 转 Base64 约 1 MB，完全没压力。

**Q：为什么不是 2:1 的图也能传？**
A：引擎里有个判断：宽高比 ≥ 1.5 才按 360° 天球投影铺；否则当成普通平面照片做视差平移。
   所以想体验真正的"环绕"，务必用 2:1。

**Q：能换成自己拍的全景照片吗？**
A：可以。手机全景（横向扫一圈那种）导出成 2:1 就能直接用；
   注意画面正中要对着你想要的"默认正前方"。

**Q：这几张图是怎么做的？能改吗？**
A：用项目里的 `tools/panorama_360.py` 渲染的（纯 numpy 光线投射，不需要 Blender/Three.js）：

```bash
# 白天 · 总览机位
python3 tools/panorama_360.py --theme day   --eye overview --width 4096 --out out_day.jpg
# 夜间 · 总览机位
python3 tools/panorama_360.py --theme night --eye overview --width 4096 --out out_night.jpg
# 白天 · 第一人称地面机位
python3 tools/panorama_360.py --theme day   --eye fps      --width 3072 --out out_fps.jpg
# 加 --preview 会额外输出一张 App 视角预览图
```

改完 `build_scene()` 里的设备/颜色，重跑命令就能生成新底图。

## 八、原理：一张 JPG 为什么能转 360°？

### 它不是"一张照片"，是"每个方向一个像素"的查找表

普通照片记录的是**平面上一个矩形**里的颜色；全景图记录的是**从视点出发、每个方向**看到的颜色。
所以它能被"剪开摊平"成 2:1 的矩形：

- 横向 = 方位角 0°～360°（x 轴就是"转了一圈"）
- 纵向 = 仰角 +90°（头顶）～ -90°（脚下）（y 轴就是"抬头/低头"）

类比：**世界地图**是平的，但你能在地图上找到地球上任何一个方向 ——
全景图就是"以你为球心"的那颗地球摊平后的地图。

### 拖动时程序只做三件事（对应 `js/scene-3d.js:564-600`）

1. 从相机拿到朝向：`angleH`（方位角）、`angleV`（俯仰角）——`scene-3d.js:574`
2. 换算成图上的百分比位置：
   `uCenter = angleH / 360° + 0.5`，`vCenter = 0.5 - angleV / 180°`——`scene-3d.js:583`
3. 以这个点为中心，按视野角 `fovX / fovY` 裁一块矩形，`ctx.drawImage` 贴到画布上——`scene-3d.js:592-600`

**图片本身从头到尾没有旋转过、也没有变形过**，只是"取景框"在图上滑动。
所以拖动是顺滑的、没有 3D 计算量的——一次裁图而已。

### 那"立体感"从哪来？

两个来源，缺一不可：

1. **图里本来就存着透视信息**：这张图是从某个视点真实"看"出来的，
   近大远小、遮挡关系、阴影方向都已经烘焙在像素里；
2. **3D 部分其实是代码另外画的**：8 个热点是带 `pos3d` 的世界坐标，
   每一帧用 `projectPoint()`（`scene-3d.js:482`）做透视投影，
   设备模型则由 `buildPlantGeometry()`（`scene-3d.js:288`）生成三角形/圆柱并做深度排序。

也就是说：**底图负责"背景看起来像真的"，热点和模型负责"能点、能动、有视差"**。
拖动时你感觉"在转"，其实是背景窗口在滑 + 热点按透视跟着动，两者叠加出来的效果。

### 定点全景相机（已实现：热点不再漂移）

上传自定义 360° 底图后，引擎自动切到「定点全景相机」：
相机固定在渲染底图的视点 `(-3.96, -26.27, 13.84)`，**拖动 = 转头，滚轮 = 变焦**，
背景按真实球面透视绘制，热点用同一相机投影，所以旋转、缩放时热点始终贴在图中设备上。
（实测：缩放/旋转前后，热点投影位置与底图对应像素偏差 < 0.3px。）
此模式下 W/A/S/D 走动与右键平移不起作用；清除 3D 底图后恢复原有自由相机。

### 全景图的边界（知道这些就不会被"骗"）

- **不能绕到物体背后看新内容**：球面上只有从这一个视点看到的信息。
  转到设备背面，看到的是"那个方向本来就有"的像素，不会凭空长出背面结构。
- **往前走，背景不会变大**：因为取景只看"朝向"，不看"位置"（`scene-3d.js` 只用了 `cam.forward`）。
  想验证：切「仅底图」按 W 往前走，画面大小不变；切「叠加」，程序化模型会真实变大。
- 视野角拉得很大时，边缘会有一点点拉伸：因为现在取的是"矩形裁切"，
  严格做法是按像素做球面反投影（工程上常改用立方体全景 6 张图）。

> 一句话总结：**它是"会跟着你转的球幕背景"，不是可自由查看的三维模型。**
> 但这正是"全景底图"该有的能力，也刚好够仿真考试用。
